# ModernUI

Themed (light / dark / follow Windows) user interface layer for OpenHoldem.
Plain Win32 + GDI+, **no MFC** inside this folder, so it can be compiled and
previewed without the rest of OpenHoldem. Only `../ModernFrameSupport.*` knows MFC.

| File | Purpose |
|------|---------|
| `ModernTheme` | Palettes, mode (System/Light/Dark), registry persistence, DWM frame attributes |
| `ModernGfx` | GDI+ helpers: fonts, rounded rects, text with ellipsis, icons, suits, double buffering |
| `ModernSvg`, `ModernIconData.h` | SVG path parser + Lucide icons (generated by `tools/gen_icons.py`) |
| `ModernMenu` | Menu model loaded from `.rc`, themed popup with mouse/keyboard handling |
| `ModernHeader` | Title bar, menu bar, toolbar, flags, status bar |
| `ModernTable` | Poker table renderer, fed by a plain `TableView` snapshot |

MFC glue (outside this folder): `../ModernFrameSupport.*` (menus, toolbars of the main window and of the
formula editor) and `../ModernControls.*` (themed buttons, tab control, tree / edit colours).

## Preview without OpenHoldem (Linux + Wine, or Windows)

```
x86_64-w64-mingw32-g++ -std=c++17 -static preview/window_preview.cpp ModernHeader.cpp \
  ModernMenu.cpp ModernTable.cpp ModernGfx.cpp ModernSvg.cpp ModernTheme.cpp \
  -o window_preview.exe -lgdiplus -lgdi32 -luser32 -ladvapi32 -lole32
wine window_preview.exe dark   # or: light, optionally "nomenu"
```

## Known limitations (milestone 1)

* The main window, the formula editor, its Hand list editor (themed 13x13 matrix,
  `../ModernHandGrid.*`) and its Find / Replace bar (`../ModernFindBar.*`) are converted.
  The Preferences are one single themed dialog (`../DialogPreferences.*`, pages described as data)
  that replaced the 20 classic property pages. New / Rename, ManualMode, OpenScrape and OHReplay
  still use native menus/controls.
* The auto-completion list of the formula editor is drawn by Scintilla itself
  (system colours): the bundled Scintilla is too old to theme it.
* Popups are single level (no sub-menus); none of the current menus needs them.
* No tooltips on the toolbar yet.
* The process is still DPI-unaware (as before, to not change window-scraping
  coordinates); the UI itself already scales with `DpiScale()`.
